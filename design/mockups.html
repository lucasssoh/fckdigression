fckdigression · draft 2

fckdigression, first pass

The project is now fckdigression: a tool that locks distractions out of your phone, with the parent code kept by someone else. DNS is the first guard, and any DNS-over-TLS server works: public, private or your own. The app, the CLI (fckd) and the TUI are built so more guards can be added later. Pick what you like at the bottom of the page.

Errors you'll actually meet

✘ This phone has 2 accounts: com.google, com.whatsapp
  Android only grants device owner on a phone with no accounts.
  Fix: remove them in Settings → Accounts, or factory-reset
       and skip sign-in, then run this again.

✘ The phone refused the install.
  Fix: in Developer options, allow installs over USB.
       Some phones also have "Install via USB" to turn on.

✘ This computer isn't authorized yet.
  Fix: unlock the phone and tap Allow on the
       "Allow USB debugging?" prompt.

✘ dns.example.com doesn't answer DNS-over-TLS.
  Check the hostname and that the phone is online.

✘ The parent code is 8 digits long. Use at least 12.
  Tip: fckd lock --generate-code prints a random 30-digit code.

! USB debugging left on (--allow-debug).
  Anyone with a cable and adb can undo the lock.

fckd --help

fckdigression 2.0 — lock distractions out of an Android phone

Usage
  fckd                         open the interactive TUI
  fckd <command> [options]

Commands
  lock [guards]     install the app and turn on the guards you pick
  status            show the lock state of the connected phone
  unlock            lift the lock (needs the parent code)
  release           lift the lock and let the app be uninstalled
  build             compile the Android app

Guards
  --dns HOST         lock Private DNS to a DNS-over-TLS server
  (more guards later: apps, schedule…)

Lock options
  --allow-reset      keep factory reset available in Settings
  --allow-vpn        allow VPN apps (a VPN bypasses Private DNS)
  --allow-debug      leave USB debugging on (adb can undo the lock)
  --generate-code    make a random 30-digit parent code and show it once

Global
  -s, --serial ID    pick a phone when several are connected
      --no-color     plain output
  -h, --help         show this help

Examples
  fckd lock --dns dns.example.com    # any DNS-over-TLS server

5 · To decide

Choices before we build

Icon

D, A, B or C, or a mix.

Suggested: D, the only one that says "focus" and not just "lock"
Names

Project and app: fckdigression. Command: fckd, short to type. On the home screen, Android cuts labels after about 12 characters, so the icon label would read fckd or FckDigress….

Suggested: command fckd, launcher label "fckd"
TUI stack

Go + Bubble Tea: rewrite the bash script as one static binary with CLI, TUI and a guard interface that new features plug into. Bash + gum: keep the script and add menus, faster but harder to grow.

Suggested: Go + Bubble Tea, since more guards are coming
PIN entry on the phone

Your code is 30 digits, dictated from abroad. Proposed: a custom keypad with groups of 5, a counter, a "show digits" toggle, and the code length saved at lock time so a wrong-length entry doesn't count as an attempt. Minimum stays 6 digits.

Suggested: as mocked up
Next guards (later, not in this pass)

Ideas that fit the device-owner model: hide or suspend chosen apps, block installs from the Play Store, time windows, a "keep Chrome on SafeSearch" policy. Tell me which ones matter, so the structure is ready for them.

Fixed constraints (the lock is already on your phone)

  • The package id fr.lucas.dnslock and dnslock.keystore stay as they are, even with the new name. Nobody sees them, and changing either means release, then reinstall on a phone with no accounts. Only the label and icon change.
  • To push the new app: unlock in the app (this turns USB debugging back on), connect the phone, run fckd lock --keep-code. It updates in place, keeps the owner rights and keeps the existing parent code, so your parents don't need to send a new one.
  • The app already installed doesn't store the code length. The new version learns it the first time the code is accepted.
  • The status keys sent by the app switch to English (locked_dns…). The new CLI will still read the old French keys so it works with the app already installed.
